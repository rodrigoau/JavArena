**JavArena** is a personal learning playground that combines two tracks in a single Maven project:

1. **Core Java** – small, focused examples of programming logic, Object-Oriented Programming, data structures and (soon) algorithms.
2. **Test Automation** – a framework covering **web** (Selenium), **Android mobile** (Appium), **REST API** (RestAssured) and **BDD** (Cucumber) testing, run with **TestNG** and reported with **Allure**.

## 🤖 Automation Framework

### Design
- **Page Object Model** – UI locators and actions live in `pages/` (web) and `screens/` (mobile); tests only call readable, chainable methods (fluent API / method chaining).
- **Driver factories with `ThreadLocal`** – `DriverFactory` and `MobileDriverFactory` keep one driver per thread, ready for parallel execution.
- **Base classes** – `BasePage` / `BaseMobilePage` wrap `WebDriverWait` (10 s) with helpers such as `waitForElementVisible`, `click` and `type`; `BaseApiTest` builds a shared RestAssured `RequestSpecification`.
- **Externalized test data** – two interchangeable sources:
  - `ConfigReader.getProperty("mobile.valid.username")` → `data/accounts.properties`
  - `JsonReader.getString("/mobile/validUser/username")` → `data/accounts.json` (Jackson, JSON Pointer syntax)
- **Data-driven API testing** – API cases are declared in JSON fixtures, no Java code needed per case.
- **BDD** – Gherkin feature files executed by Cucumber on top of TestNG.
- **Allure annotations** – tests are tagged with `@Epic`, `@Feature`, `@Story` and `@Description`; Cucumber scenarios are reported through the `AllureCucumber7Jvm` plugin.

### 🌐 Web tests
- Target site: [klauders.com/automate-the-internet](https://klauders.com/automate-the-internet)
- `BaseTest` opens the browser once per suite (`@BeforeSuite`) and navigates to the target site.
- `KlaudersTest` – validates the browser title, the page header through a Page Object, and a chained click flow.
- Browser is selected through the `browser` parameter in `testng_web.xml` (`chrome` by default, also `firefox` and `edge`).

### 📱 Mobile tests (Android)
- App under test: *Automate the Internet* Android APK.
- `BaseMobileTest` creates a fresh Appium session per test method (`@BeforeMethod` / `@AfterMethod`).
- `HomeScreenTest` – opens the *Login & Sign-up* card.
- `LoginScreenTest` – logs in with valid credentials read from **properties** and from **JSON**, asserting the welcome message.
- Device and app are configured in `testng_mobile.xml` via the `platformName`, `deviceName` and `appPath` parameters.
- The Appium server is expected at `http://127.0.0.1:4723`.

### 🥒 BDD tests (Cucumber)
- `features/login.feature` – *Successful login with valid credentials from JSON file*.
- `LoginSteps` – step definitions that reuse the same Screen Objects and `JsonReader`; Cucumber `@Before` / `@After` hooks start and quit the Appium driver.
- `CucumberRunnerTest` – extends `AbstractTestNGCucumberTests` (glue: `com.rodrigo.tests.mobile`) and produces:
  - console output (`pretty`)
  - an HTML report at `target/cucumber-reports.html`
  - Allure results
- ⚠️ The device name and APK path are currently hard-coded in the `@Before` hook of `LoginSteps`.

### 🔌 API tests (RestAssured)
- Base URI: `https://klauders.com`, JSON content type, with request/response/error logging filters (`BaseApiTest`).
- `ApisTests` – a classic hand-written test that checks a `200` status on the users endpoint.
- `TemplateApiTest` – a **generic, data-driven engine**:
  1. A `@DataProvider` loads every `*.json` file in `src/test/java/com/rodrigo/tests/api/fixtures/`.
  2. Each top-level entry with `expectedResults` becomes an independent test run (named after its `testName`, also in Allure).
  3. The request is built from the fixture (endpoint, method, headers, path/query params, body) and sent.
  4. The status code is asserted, and the response is compared **recursively** against `expectedResults`. Every difference is reported with its path (e.g. `$.data[0].name`) and attached to Allure together with the expected and actual JSON.

#### Fixture format

```jsonc
{
  "testName": "Users",              // optional – default name for the cases in this file
  "endpoint": "/automate-the-internet",
  "method": "GET",                  // optional – default GET
  "headers": { },                   // optional – applied to every case

  "getPaginatedUsers": {            // one test case
    "testName": "Users - page 1",   // optional – default "file.json -> caseKey"
    "description": "...",           // optional
    "endpoint": "/other-path",      // optional – overrides the file value
    "method": "POST",               // optional – overrides the file value
    "pathParams":  { },             // optional
    "queryParams": { "api": "users", "page": 1, "perPage": 8 },
    "headers":     { },             // optional – merged with the file headers
    "body":        { },             // optional – request body
    "expectedStatus": 200,          // optional – default 200
    "ignoreFields": ["requestId"],  // optional – dotted paths without indexes (e.g. data.name)
    "expectedResults": { "data": [ ... ] }
  }
}
```

Comparison rules: every field declared in `expectedResults` must exist and match in the response (extra response fields are allowed), arrays must have the same size and are compared element by element, and numbers are compared by value (`49` == `49.0`).

> To add a new API test, just drop a new `.json` file (or a new case) into `fixtures/` — no Java changes required.

## ✅ Prerequisites

- **JDK 25**
- **Maven 3.9+**
- **Web:** Chrome, Firefox or Edge installed (Selenium Manager downloads the drivers automatically).
- **Mobile / BDD:**
  - Node.js + Appium 2 with the UiAutomator2 driver:
    ```bash
    npm install -g appium
    appium driver install uiautomator2
    ```
  - Android SDK with an emulator (e.g. `Pixel_10`) or a real device connected via `adb`.
  - The APK path set in `src/test/resources/testng_mobile.xml` (`appPath`) and in `LoginSteps` (for Cucumber).
- **API:** internet access to `https://klauders.com`.
- **Test data:** credentials in either (or both) files:
  - `src/test/resources/data/accounts.properties`
    ```properties
    mobile.valid.username=<your-user>
    mobile.valid.password=<your-password>
    ```
  - `src/test/resources/data/accounts.json`
    ```json
    {
      "mobile": {
        "validUser":   { "username": "<your-user>", "password": "<your-password>", "successMessage": "..." },
        "invalidUser": { "username": "...", "password": "...", "errorMessage": "..." }
      }
    }
    ```
- **Reports (optional):** [Allure CLI](https://allurereport.org/docs/install/).

## ▶️ Running the Tests

```bash
# Clone and build
git clone <repo-url>
cd JavArena
mvn clean compile

# Web suite
mvn test -Dsurefire.suiteXmlFiles=src/test/resources/testng_web.xml

# API suite (data-driven fixtures)
mvn test -Dsurefire.suiteXmlFiles=src/test/resources/testng-api.xml

# Mobile suite (start Appium and the emulator first)
appium
mvn test -Dsurefire.suiteXmlFiles=src/test/resources/testng_mobile.xml

# BDD / Cucumber scenarios (Appium + emulator required)
mvn test -Dtest=CucumberRunnerTest
```

You can also right-click a suite XML, a test class or `login.feature` in IntelliJ IDEA and select **Run**.

> ℹ️ No suite is registered in the Surefire `<suiteXmlFiles>` of `pom.xml` yet, so always pass the suite (or `-Dtest`) explicitly.

## 📊 Allure Reports

Every run writes raw results to `allure-results/` (TestNG and Cucumber tests alike). To view them:

```bash
# Using the Maven plugin
mvn allure:serve

# Or using the Allure CLI
allure serve allure-results
```

Failed API comparisons include three attachments: **Diferencias**, **Esperado** and **Recibido**.
