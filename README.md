**JavArena** is a personal learning playground that combines two tracks in a single Maven project:

1. **Core Java** – small, focused examples of programming logic, Object-Oriented Programming, data structures and (soon) algorithms.
2. **Test Automation** – a Page Object Model framework for **web** (Selenium) and **Android mobile** (Appium) testing, run with **TestNG** and reported with **Allure**.

## 📘 Core Java Modules

Each class has its own `main` method and can be run directly from the IDE.

| Package | Class | Topic |
|---------|-------|-------|
| `core.logic` | `EntryPoint` | `if / else` decisions |
| `core.oop.workspace1` | `Animal`, `Dog`, `EntryPoint` | Abstract classes, inheritance, `@Override`, polymorphism |
| `core.oop.workspace2` | `Book`, `Library` | Java `record`s and their auto-generated accessors |
| `core.datastructures` | `Arrays` | Array declaration, initialization and iteration |
| `core.datastructures` | `JavaCollections` | `List`, `Set` (`TreeSet`) and a cheat sheet of the Collections Framework |
| `core.datastructures` | `Inventory` | `ArrayList` + `HashMap` used as a simple stock lookup |
| `core.algorithms` | `EntryPoint` | Placeholder for upcoming algorithm exercises |

> ℹ️ Some classes (`Inventory`, `Library`) use the Java 25 simplified `main` method (no `public` modifier), so a JDK 25 is required.

## 🤖 Automation Framework

### Design
- **Page Object Model** – UI locators and actions live in `pages/` (web) and `screens/` (mobile); tests only call readable, chainable methods (method chaining / fluent API).
- **Driver factories with `ThreadLocal`** – `DriverFactory` and `MobileDriverFactory` keep one driver per thread, ready for parallel execution.
- **Base classes** – `BasePage` / `BaseMobilePage` wrap `WebDriverWait` with helpers such as `waitForElementVisible`, `click` and `type`.
- **Externalized test data** – `ConfigReader` reads credentials from `src/test/resources/data/accounts.properties`.
- **Allure annotations** – tests are tagged with `@Epic`, `@Feature`, `@Story` and `@Description`.

### Web tests
- Target site: [klauders.com/automate-the-internet](https://klauders.com/automate-the-internet)
- `KlaudersTest` – validates the browser title, the page header through a Page Object, and a chained click flow.
- Browser is selected through the `browser` parameter in `testng_web.xml` (`chrome` by default, also `firefox` and `edge`).

### Mobile tests (Android)
- App under test: *Automate the Internet* Android APK.
- `HomeScreenTest` / `LoginScreenTest` – open the Login & Sign-up card and log in with valid credentials, asserting the welcome message.
- Device and app are configured in `testng_mobile.xml` via the `platformName`, `deviceName` and `appPath` parameters.
- The Appium server is expected at `http://127.0.0.1:4723`.

## ✅ Prerequisites

- **JDK 25**
- **Maven 3.9+**
- **Web:** Chrome, Firefox or Edge installed (Selenium Manager downloads the drivers automatically).
- **Mobile:**
  - Node.js + Appium 2 with the UiAutomator2 driver:
    ```bash
    npm install -g appium
    appium driver install uiautomator2
    ```
  - Android SDK with an emulator (e.g. `Pixel_10`) or a real device connected via `adb`.
  - The APK path set in `src/test/resources/testng_mobile.xml` (`appPath`).
- **Test data:** a `src/test/resources/data/accounts.properties` file with:
  ```properties
  mobile.valid.username=<your-user>
  mobile.valid.password=<your-password>
  ```
- **Reports (optional):** [Allure CLI](https://allurereport.org/docs/install/).

## ▶️ Running the Tests

```bash
# Clone and build
git clone <repo-url>
cd JavArena
mvn clean compile

# Web suite
mvn test -Dsurefire.suiteXmlFiles=src/test/resources/testng_web.xml

# Mobile suite (start Appium and the emulator first)
appium
mvn test -Dsurefire.suiteXmlFiles=src/test/resources/testng_mobile.xml
```

You can also right-click `testng_web.xml` / `testng_mobile.xml` in IntelliJ IDEA and select **Run**.

## 📊 Allure Reports

Every run writes raw results to `allure-results/`. To view them:

```bash
# Using the Maven plugin
mvn allure:serve

# Or using the Allure CLI
allure serve allure-results
```
